## 1. 보류 결정

### ADMIN의 다른 사람 참여 기록 수정

**상태: 보류**

관리자가 다른 사람의 거리/기록/메모를 고치는 기능은 지금 만들지 않는다.

이유:

- 뮤런의 기본 모델은 “참여자가 자기 기록을 직접 적는다”이다.
- 관리자가 임의 수정하면 기록 책임 경계가 흐려진다.
- 제대로 만들려면 행별 편집 UI, 변경 이력, 실수 방지 장치가 필요하다.

재검토 조건:

- 부원이 기록 입력을 자주 잊어 운영진 대리 입력 요구가 반복될 때
- 대회/행사처럼 운영진이 공식 기록을 정정해야 하는 상황이 생길 때

### HEIC 표시용 변환

**상태: 보류**

HEIC 업로드는 허용하지만, 서버에서 JPEG/WebP 표시용 파생본을 만드는 작업은 아직 하지 않는다.

이유:

- 원본 보존 정책을 유지해야 한다.
- 파생본을 만들면 원본/표시용 파일의 수명주기, orphan cleanup, 백업 범위가 복잡해진다.
- 현재 dogfooding에서는 jpg 업로드로 충분했다.

재검토 조건:

- iPhone 사용자가 HEIC 사진을 자주 올리고 Chrome/Android에서 사진이 깨진다는 피드백이 반복될 때

### 백업 자동화

**상태: 보류**

cron/restic 기반 자동 백업은 이번 범위에서 제외한다.

이유:

- 백업은 생성보다 복구 리허설이 중요하다.
- N100을 다른 용도로도 사용할 예정이라 서버 전체 백업 정책과 함께 잡는 편이 낫다.
- 현재는 Docker volume 위치를 알고 수동 백업할 수 있다.

재검토 조건:

- 실제 기록이 충분히 쌓여 데이터 손실 비용이 커졌을 때
- 외부 디스크/NAS/원격 저장소 중 백업 위치를 확정했을 때
